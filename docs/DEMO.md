# 固定演示与回归

## 启动

```powershell
npm ci
npm run demo
```

打开 http://127.0.0.1:5190/demo.html 。不要改为日常演示的 5173 端口。
演示只使用本机模拟 API；真实模型插件不加载，浏览器 connect-src 仅允许本机。页面顶部及模型名称均标记模拟。不需要真实密钥，不验证服务商能力，不产生付费生成。
演示图是规则绘制的矩形产品示意，验证链路和文件交付，不用于评价工业设计或 AI 质量。

## 固定项目与起点

演示 A 为无声翻面休息牌：包括同一条设计简报、三方向概念、深化笔记、分析记录、统一外观规范和冻结 V1；演示 B 用于验证隔离。
概念和冻结为预置检查点，演示操作不会声称现场完成真实市场调研、实测或认证。原始深化→优化→冻结逻辑由 tests/workflowModels.test.mjs 和 tests/development.test.mjs等现有测试覆盖。
只在此来源无项目时初始化；刷新不重置人工修改。重演请使用新浏览器配置文件或无痕窗口，仅清除 5190 的演示数据，不能清除日常工作台数据。

## 固定操作路线与预期

1. 首页对话：输入“把交互做得更安静”，发送；得到 DEMO 模拟回复。
2. 切到 Concept Studio，查看预置三个方向、选定方案并点击继续深化。检查深化、可行性、原创性及冻结记录均可查看；这是固定检查点，不重新执行实测。
3. 概念图与展板：英文 Prompt 自动填入；生成10款草图，在原图框选完整方案，确认选中。
4. 生成选定产品高清效果图，确认外观，再生成产品概念展示图。
5. 第三步点击 AI 根据产品图推荐参数，再生成全部五张图；展开各张查看独立图片。
6. 第六步展开包装展开稿，查看自动默认值；修改包装文案，生成打样文件并下载 ZIP。ZIP 内含 artwork.svg、dieline.svg、dieline.dxf 和说明资料。
7. 设计报告：等待 AI 填入资料，把产品说明改为“人工修正：保留此产品说明”；刷新后重新进入，应保持修改。
8. 生成策划报告，展开第一章，修改正文后导出图文 PPTX；文件须包含人工正文和产品图。
9. 切到演示 B，不能看到 A 的正文和图片；返回 A，修改仍在。

## 自动浏览器回归

```powershell
npx playwright install chromium
npm run test:e2e
```

测试自行启动独立 5190 服务，并使用隔离浏览器上下文；运行前先停止手动 demo 服务。不会自动复用已有工作台。
GitHub 的 browser-regression 运行 Chromium 并保存失败截图、trace 和 HTML 报告七天。
本轮覆盖：报告自动填入后的人工修正/刷新/项目切换，草图框选与效果图确认、工程参数和五图、包装 ZIP 内容、报告 PPTX 人工正文。
`npm run verify` 保持快速的 Lint、115项测试与构建；浏览器测试作为独立 CI 闸门，不用把真实 API 接入测试。
